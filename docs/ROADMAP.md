# Roadmap: переработка Password Manager

Живой план работ. Выполняем **по порядку**, отмечаем `[x]` сразу после завершения.
Каждая задача проходит цикл: **реализация → `code-reviewer` → `task-verifier` → отметка здесь**
(запуск цикла: скилл `/next-step`).

Контекст: приложение личное, ставится только как APK (в Google Play больше не публикуется).
Значит, обратная совместимость с чужими пользователями не нужна, но **мои данные терять нельзя**.

- [x] 2.5 Лишнее (Yandex Ads удаляем, решено): `react-native-camera` (deprecated), разрешения в `AndroidManifest`

## Фаза 3. Целевая архитектура (решение вместе с пользователем)

- [ ] 3.1 Выбрать путь: апгрейд RN 0.68 → актуальная версия на месте **или** новый проект (RN CLI / Expo) с переносом логики. Рекомендация: новый проект, потому что разрыв в версиях слишком большой
- [x] 3.1a Архитектура кода: FSD + DI-сервисы (`docs/ARCHITECTURE.md`)
- [ ] 3.2 Новая модель шифрования: мастер-пароль/ключ → Argon2id/PBKDF2 (много итераций) → AES-256-GCM, версионированный формат; ключ данных 256 бит из CSPRNG; контрольное значение для проверки ключа при вводе (C1–C4); ключ в Android Keystore, разблокировка биометрией
- [ ] 3.3 Схема хранения в Firestore (документ на запись или версия + атомарные обновления), формат с версией для миграций; случайные UUID вместо timestamp, даты внутри шифротекста (L3); надёжная запись: явные ошибки, индикатор синхронизации, очередь офлайн-изменений (D1, D3); безопасный порядок удаления аккаунта: данные → Auth → локальное хранилище (D4)
- [ ] 3.4 План миграции старых данных: расшифровать старым способом → зашифровать новым (локально, на устройстве)
