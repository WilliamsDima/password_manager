# Roadmap: переработка Password Manager

Живой план работ. Выполняем **по порядку**, отмечаем `[x]` сразу после завершения.
Каждая задача проходит цикл: **реализация → `code-reviewer` → `task-verifier` → отметка здесь**
(запуск цикла: скилл `/next-step`).

Контекст: приложение личное, ставится только как APK (в Google Play больше не публикуется).
Значит, обратная совместимость с чужими пользователями не нужна, но **мои данные терять нельзя**.

## Фаза 2. Аудит безопасности

Результат: `docs/SECURITY_AUDIT.md` со списком проблем, их критичностью и решением.
Кандидаты на проверку (гипотезы, подтвердить по коду):
- [ ] 2.1 Криптография: `crypto-js@3` (соль через `Math.random`), KDF `EVP_BytesToKey`/MD5 с одной итерацией, AES-CBC без MAC, энтропия генерируемого ключа
- [ ] 2.2 Хранение секретов: PIN в открытом виде, нет биометрии, нет авто-блокировки по таймауту/уходу в фон
- [ ] 2.3 Утечки на устройстве: нет `FLAG_SECURE` (скриншоты/превью в списке задач), буфер обмена не очищается, логи `console.log` с ошибками расшифровки
- [ ] 2.4 Firebase: правила Firestore (доступ только к своему документу?), App Check, ограничения API-ключа
- [ ] 2.5 Лишнее (Yandex Ads удаляем, решено): `react-native-camera` (deprecated), разрешения в `AndroidManifest`
- [ ] 2.6 Данные: перезапись всего массива `items` целиком (риск потери при гонках/ошибке)

## Фаза 3. Целевая архитектура (решение вместе с пользователем)

- [ ] 3.1 Выбрать путь: апгрейд RN 0.68 → актуальная версия на месте **или** новый проект (RN CLI / Expo) с переносом логики. Рекомендация: новый проект, потому что разрыв в версиях слишком большой
- [x] 3.1a Архитектура кода: FSD + DI-сервисы (`docs/ARCHITECTURE.md`)
- [ ] 3.2 Новая модель шифрования: мастер-пароль/ключ → Argon2id/PBKDF2 (много итераций) → AES-256-GCM; ключ в Android Keystore, разблокировка биометрией
- [ ] 3.3 Схема хранения в Firestore (документ на запись или версия + атомарные обновления), формат с версией для миграций
