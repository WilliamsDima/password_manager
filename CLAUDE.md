# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Password manager for Android (package `com.eclipse.account_manager`). It was on Google Play; now it is distributed only as an APK to the owner and possibly friends. Registration stays open, so per-user isolation relies on Firestore rules ([firestore.rules](firestore.rules)). Entries are encrypted on the device before they are saved to Firebase Firestore. UI language: Russian only.

The v2 rewrite is feature-complete and merged into `master` (2026-11-26; release build checked on a phone); what is left is in [docs/ROADMAP.md](docs/ROADMAP.md) (phase 7):
- **Root = v2**: a new Expo app (Expo SDK 58, React Native 0.88, React 19, TypeScript 6) built per [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) and [docs/CRYPTO.md](docs/CRYPTO.md).
- **v1 is gone**: the old RN 0.68 app was deleted from the repo (2026-11-26, after the owner migrated and deleted the old data). Its code stays in git history; its data format and the migration are described in [docs/CRYPTO.md](docs/CRYPTO.md) §6.

## Commands (v2, repo root)

```bash
npm install
npm start                 # Expo dev server (needs a development build, not Expo Go: native Firebase)
npm run android           # expo run:android: build and install a debug build on a device or emulator
npm run prebuild          # regenerate android/ from app.json (Continuous Native Generation)
npm run icons             # redraw the app icon, adaptive icon layers and splash images (assets/, scripts/build-icons.mjs)
npm run typecheck         # tsc --noEmit
npm run lint              # eslint (flat config: eslint.config.js)
npm run format            # prettier --write
npm test                  # jest (preset jest-expo); single file: npx jest src/shared/lib/logger
npm run test:rules        # Firestore rules in the emulator (firestore.rules; needs Java, downloads the emulator once)
npm run check             # typecheck + lint + format:check + test; run before declaring a task done
cd android && ./gradlew assembleRelease   # release APK (after `npm run prebuild`) → android/app/build/outputs/apk/release/app-release.apk
npx expo install <pkg>    # always use instead of npm i for Expo/RN packages (SDK-compatible versions)
```

- `android/` is generated by `expo prebuild` and gitignored. Never edit it by hand: configure native behavior in [app.json](app.json) and config plugins.
- Expo APIs change every SDK. Check the versioned docs (`https://docs.expo.dev/versions/v58.0.0/`) or the installed package's types instead of relying on memory.

### Required untracked files
- `google-services.json` in the repo root (download it from the Firebase console, project settings, or restore it from `secrets/firebase/`). Needed by `@react-native-firebase` at prebuild.
- Release signing key: a **new** v2 key (not the v1 Play key), outside the repo at `~/.android-keys/password-manager/release.jks`, alias `pm-release`. Path and passwords are in `~/.gradle/gradle.properties` (`PM_RELEASE_STORE_FILE`, `PM_RELEASE_KEY_ALIAS`, `PM_RELEASE_STORE_PASSWORD`, `PM_RELEASE_KEY_PASSWORD`). On another machine copy both files; without them `assembleRelease` fails (it never falls back to the debug key). Wired by the config plugin `plugins/with-release-signing.js`. Build: `cd android && ./gradlew assembleRelease` → `android/app/build/outputs/apk/release/app-release.apk`. v1 (Play key) cannot be updated in place: uninstall it first.

### Secrets folder (`secrets/`, gitignored)
One local folder holds a copy of every secret, so that it can be saved in one go (encrypted archive, password manager, offline drive). **Never commit it; never print or paste file contents.** Refresh it with `npm run secrets:collect` ([scripts/collect-secrets.mjs](scripts/collect-secrets.mjs)) after any secret changes; **add every new secret to the `SECRETS` list in that script.** Layout and where each file must be put back on a new machine:

| In `secrets/` | Restore to |
|---|---|
| `firebase/google-services.json` | repo root `google-services.json` |
| `android/release.jks` | `~/.android-keys/password-manager/release.jks` |
| `android/gradle.properties` | `~/.gradle/gradle.properties` (fix the absolute `PM_RELEASE_STORE_FILE` path for the new machine) |
| `claude/telegram.json` | `.claude/telegram.json` |
| `backups/` | `backups/` (Firestore ciphertext backups) |

The v1 encryption key (text/QR) is not a file: store it in your password manager. Without `release.jks` + passwords v2 cannot be updated in place (see 4.4a in the roadmap).

## v2 setup notes

- Firebase: native `@react-native-firebase` (app, auth, firestore), modular API. Plugins in `app.json`.
- `expo-build-properties`: R8 + resource shrinking in release, `usesCleartextTraffic=false`, network inspector off. Unneeded permissions are removed via `android.blockedPermissions`. `allowBackup=false`.
- `versionCode` must stay greater than the Play version (8) so v2 installs over it.
- `modules/pm-kdf/`: local Expo module (Kotlin, BouncyCastle scrypt) for the app-password KDF, autolinked from `modules/`; it needs a native rebuild (`npm run android`), not just a JS reload. JS side: `shared/services/crypto/native-scrypt-kdf.ts`.
- Path alias `@/*` → `src/*` (tsconfig `paths`, jest `moduleNameMapper`).
- ESLint enforces the FSD rules from ARCHITECTURE.md: layer direction and no cross-slice imports (`eslint-plugin-boundaries`), public-API-only imports (`no-restricted-imports`), no `let`, no `any`, no `@ts-ignore`, `no-console` (only `src/shared/lib/logger` may use console). Release bundles strip `console.*` (babel `transform-remove-console`), and the logger is disabled when `!__DEV__`.
- TypeScript 6: `types` defaults to empty, so `tsconfig.json` lists `"types": ["jest"]`. `baseUrl` is deprecated, so don't add it.
- Styling: `react-native-unistyles` 3 (+ `react-native-nitro-modules`, native: rebuild after install or update, and restart Metro with `--clear`). `index.ts` must import `@/shared/theme/unistyles` first (it registers the themes); the Babel plugin is configured with `root: "src"`. `useAppTheme()` / `useColorScheme()` are only for non-style props (ActivityIndicator color, navigation theme). Jest: `react-native-unistyles/mocks` + `jest.setup.js`.
- **Layout rule (the owner's requirement: the app must look the same and be readable on every device):** every screen is built from `Screen` / `Page` / `ScrollScreen` (`src/shared/ui/layout.tsx`): they keep content out of the status bar, cut-out, navigation bar and keyboard (system insets, the app is edge to edge) and limit it to a 560 dp column on wide screens. Do not put content directly into a plain `View` at the screen root. **Check every new or changed screen yourself, with screenshots, in four conditions:** default, dark theme with font scale 1.6, small screen (720x1280 at 320 dpi), wide screen (1600x2560 at 320 dpi). Run `scripts/layout-shots.sh <dir>` and look at the images. Screenshots are black because of `FLAG_SECURE`; start Metro as `EXPO_PUBLIC_ALLOW_SCREENSHOTS=1 npx expo start --clear` (debug builds only: the switch is a constant `false` in release, `__DEV__`).
- Code style (Prettier): tabs, no semicolons, double quotes, width 100. Markdown is not auto-formatted.
- **JSX rules** (the owner's rules, enforced by `no-restricted-syntax` in `eslint.config.js`): the JSX holds no logic, everything is prepared above it in hooks.
  - No inline style objects (`style={{...}}`) and no style arrays built in JSX. Static styles: `StyleSheet.create`. Themed and conditional styles: `StyleSheet.create(theme => ...)` from `react-native-unistyles` with `variants` (boolean keys `true`/`false`) and `styles.useVariants({...})` as the first statement of the component. Read variant styles only inside the component body (the Babel plugin gives that scope its own copy): a function declared outside it sees styles without variants. Anything else conditional goes into a `useMemo` variable.
  - No functions in JSX props (`onPress={() => ...}`, `style={({ pressed }) => ...}`): extract a named `onX` handler with `useCallback`. For lists, build `items` in `useMemo` and give per-item handlers to a small item component.
  - No computed values in JSX props (ternaries, template strings, `&&`, calls, comparisons, object and array literals): compute them in `useMemo` (usually one `view` object per component) and pass `view.x`. Plain identifiers, member reads and handler names are fine.
  - Empty branch of a JSX conditional is `<></>`, never `null` (so React Native never renders a stray value outside `<Text>`).
  - Hooks go above any early `return`.

## Old v1 data format (for the migration code only)

- Encryption: one key per user, `CryptoJS.AES.encrypt(JSON.stringify(value), key)` (OpenSSL "Salted__" format, `EVP_BytesToKey`/MD5, AES-256-CBC), on both `title` and `message` (`{login, password, description}`) of each item. Firestore `users/{uid}` = `{id, email, displayName, dateCreate, items: [{id: timestamp, title, message}]}`; the whole `items` array was rewritten on each change. The decryptor is `shared/services/legacy-decryptor`; the migration is `features/vault-migration`.
- Known problems of v1: [docs/SECURITY_AUDIT.md](docs/SECURITY_AUDIT.md).

## Work process

- The plan lives in [docs/ROADMAP.md](docs/ROADMAP.md): read it at the start of a session, keep "Текущий статус" and the checkboxes up to date, and record decisions in "Журнал решений".
- Each task: implement → `code-reviewer` agent → fixes → `task-verifier` agent → mark done. The `/next-step` skill runs this cycle.
- Decided: the app is never published (APK only); one UI language (Russian); no external links of the app itself (store, "leave a review", developer pages), no language switcher; no ads. The one link is the owner's own: the address saved in an entry opens in the browser (`features/open-url`, http/https only, `toOpenableUrl`).
- **Architecture for all new code: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)** (FSD layers + class-based services behind interfaces, wired only in `app/di/container.ts`; RTK Query endpoints use `queryFn` with repositories from `extra`). Code rules: TS strict, no `let`, no `any`, no `@ts-ignore`, functional components only.
- Encryption, key handling, Firestore schema, migration and in-app backup: [docs/CRYPTO.md](docs/CRYPTO.md).
- Git: `master` holds v2 (the v1 history stays in it). New work goes into a branch (`feature/…`, `fix/…`) and is merged into `master` when the owner asks. Commit messages follow Conventional Commits (`feat:`, `fix:`, `refactor:`, `chore:`, `docs:`, `build:`, `test:`, `style:`, `perf:`, `ci:`; optional scope, e.g. `feat(crypto): ...`; imperative, English subject line). **Never commit or push without the user's explicit permission in the current conversation**: after a task is done, propose the commit message and wait.
- Telegram notifications: `.claude/hooks/telegram-notify.mjs` (Stop/Notification hooks), secrets in gitignored `.claude/telegram.json`.
- Data backup: `node scripts/backup-firestore.mjs` → `backups/` (gitignored, ciphertext only; exports the v1 `items` and the v2 `entries`).
- **Release build:** raise `android.versionCode` in `app.json` for every APK that is given to the owner (the phone installs a build only if the code is not lower), run `npm run prebuild`, then `./gradlew assembleRelease`. **Always install and launch the release APK on the emulator (Android 14+: `Pixel_9_Pro`) before sending it to the owner** (`adb uninstall` the debug app first, the signatures differ): a release-only crash (for example a blocked permission a native module needs) is invisible in debug. Check the result with `apksigner verify --print-certs` (certificate SHA-256 must end in `…4B:40:00`, see the secrets table) and `aapt dump badging` (no CAMERA permission until the QR scanner exists). The release APK is signed with the key from `~/.gradle/gradle.properties`; it never falls back to the debug key. Release builds are `arm64-v8a` only (`buildArchs` in `app.json`, ~34 MB; a universal APK is ~125 MB). **After every release build send the APK to the owner's Telegram bot**: `node .claude/hooks/telegram-notify.mjs --document <apk> "<version, versionCode, SHA-256>"` (the Bot API accepts files up to 50 MB; the script refuses larger ones) and copy it to `~/Downloads/password-manager-<version>-build<versionCode>-arm64-release.apk`.
- Source layout (FSD): `entities/{entry,session}`, `features/{copy-secret,delete-entry,edit-entry,lock-mode,open-url,switch-theme,toggle-favorite,vault-backup,vault-migration}`, `widgets/{entry-list,onboarding}`, `pages/{entry-details,entry-edit,settings,sign-in,unlock,vault,vault-setup}`.
