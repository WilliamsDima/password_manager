# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Password manager for Android (package `com.eclipse.account_manager`). It was on Google Play; now it is distributed only as an APK to the owner and possibly friends. Registration stays open, so per-user isolation relies on Firestore rules ([firestore.rules](firestore.rules)). Entries are encrypted on the device before they are saved to Firebase Firestore. UI language: Russian only.

The repo is mid-rewrite (branch `feature/v2-rework`):
- **Root = v2**: a new Expo app (Expo SDK 58, React Native 0.88, React 19, TypeScript 6) built per [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) and [docs/CRYPTO.md](docs/CRYPTO.md).
- **[legacy/](legacy/) = v1**: the old RN 0.68 app, kept read-only as reference for porting and migration until phase 7. Do not modify it. It is excluded from tsc, ESLint, Prettier and Jest.

## Commands (v2, repo root)

```bash
npm install
npm start                 # Expo dev server (needs a development build, not Expo Go: native Firebase)
npm run android           # expo run:android: build and install a debug build on a device or emulator
npm run prebuild          # regenerate android/ from app.json (Continuous Native Generation)
npm run typecheck         # tsc --noEmit
npm run lint              # eslint (flat config: eslint.config.js)
npm run format            # prettier --write
npm test                  # jest (preset jest-expo); single file: npx jest src/shared/lib/logger
npm run test:rules        # Firestore rules in the emulator (firestore.rules; needs Java, downloads the emulator once)
npm run check             # typecheck + lint + format:check + test; run before declaring a task done
npx expo install <pkg>    # always use instead of npm i for Expo/RN packages (SDK-compatible versions)
```

- `android/` is generated by `expo prebuild` and gitignored. Never edit it by hand: configure native behavior in [app.json](app.json) and config plugins.
- Expo APIs change every SDK. Check the versioned docs (`https://docs.expo.dev/versions/v58.0.0/`) or the installed package's types instead of relying on memory.

### Required untracked files
- `google-services.json` in the repo root (copy of `legacy/Android/app/google-services.json`). Needed by `@react-native-firebase` at prebuild.
- Release signing key: a **new** v2 key (not the v1 Play key), outside the repo at `~/.android-keys/password-manager/release.jks`, alias `pm-release`. Path and passwords are in `~/.gradle/gradle.properties` (`PM_RELEASE_STORE_FILE`, `PM_RELEASE_KEY_ALIAS`, `PM_RELEASE_STORE_PASSWORD`, `PM_RELEASE_KEY_PASSWORD`). On another machine copy both files; without them `assembleRelease` fails (it never falls back to the debug key). Wired by the config plugin `plugins/with-release-signing.js`. Build: `cd android && ./gradlew assembleRelease` → `android/app/build/outputs/apk/release/app-release.apk`. v1 (Play key) cannot be updated in place: uninstall it first.

### Secrets folder (`secrets/`, gitignored)
One local folder holds a copy of every secret, so that it can be saved in one go (encrypted archive, password manager, offline drive). **Never commit it; never print or paste file contents.** Refresh it with `npm run secrets:collect` ([scripts/collect-secrets.mjs](scripts/collect-secrets.mjs)) after any secret changes; **add every new secret to the `SECRETS` list in that script.** Layout and where each file must be put back on a new machine:

| In `secrets/` | Restore to |
|---|---|
| `firebase/google-services.json` | repo root `google-services.json` |
| `firebase/firebase.ts` | `legacy/src/config/firebase.ts` (only for `scripts/backup-firestore.mjs`) |
| `android/release.jks` | `~/.android-keys/password-manager/release.jks` |
| `android/gradle.properties` | `~/.gradle/gradle.properties` (fix the absolute `PM_RELEASE_STORE_FILE` path for the new machine) |
| `android/v1-play-key.jks`, `android/private_key.pepk` | v1 Play key and its upload file (`legacy/Android/app/`; copy once from the old machine) |
| `claude/telegram.json` | `.claude/telegram.json` |
| `backups/` | `backups/` (Firestore ciphertext backups) |

The v1 encryption key (text/QR) is not a file: store it in your password manager. Without `release.jks` + passwords v2 cannot be updated in place (see 4.4a in the roadmap).

## v2 setup notes

- Firebase: native `@react-native-firebase` (app, auth, firestore), modular API. Plugins in `app.json`.
- `expo-build-properties`: R8 + resource shrinking in release, `usesCleartextTraffic=false`, network inspector off. Unneeded permissions are removed via `android.blockedPermissions`. `allowBackup=false`.
- `versionCode` must stay greater than the Play version (8) so v2 installs over it.
- `modules/pm-kdf/`: local Expo module (Kotlin, BouncyCastle scrypt) for the app-password KDF, autolinked from `modules/`; it needs a native rebuild (`npm run android`), not just a JS reload. JS side: `shared/services/crypto/native-scrypt-kdf.ts`.
- Path alias `@/*` → `src/*` (tsconfig `paths`, jest `moduleNameMapper`).
- ESLint enforces the FSD rules from ARCHITECTURE.md: layer direction and no cross-slice imports (`eslint-plugin-boundaries`), public-API-only imports (`no-restricted-imports`), no `let`, no `any`, no `@ts-ignore`, `no-console` (only `src/shared/lib/logger` may use console). Release bundles strip `console.*` (babel `transform-remove-console`), and the logger is disabled when `!__DEV__`.
- TypeScript 6: `types` defaults to empty, so `tsconfig.json` lists `"types": ["jest"]`. `baseUrl` is deprecated, so don't add it.
- Code style (Prettier): tabs, no semicolons, double quotes, width 100. Markdown is not auto-formatted.
- **JSX rules** (the owner's rules, enforced by `no-restricted-syntax` in `eslint.config.js`): the JSX holds no logic, everything is prepared above it in hooks.
  - No inline style objects (`style={{...}}`) and no style arrays built in JSX. Static styles: `StyleSheet.create`. Conditional or themed styles: `useThemedStyles(createStyles)` (`@/shared/theme`) with variants as separate named styles (`selected ? styles.a : styles.b`), or a `useMemo` variable.
  - No functions in JSX props (`onPress={() => ...}`, `style={({ pressed }) => ...}`): extract a named `onX` handler with `useCallback`. For lists, build `items` in `useMemo` and give per-item handlers to a small item component.
  - No computed values in JSX props (ternaries, template strings, `&&`, calls, comparisons): compute them in `useMemo` (usually one `view` object per component) and pass `view.x`. Plain identifiers, member reads and handler names are fine.
  - Empty branch of a JSX conditional is `<></>`, never `null` (so React Native never renders a stray value outside `<Text>`).
  - Hooks go above any early `return`.

## Legacy v1 (legacy/), for reference and migration

- RN 0.68, Redux slice with side effects in reducers, Atomic Design components, i18next (ru/en/uk), Firebase JS SDK (`firestore/lite`). Its Firebase config is in gitignored `legacy/src/config/firebase.ts`. `scripts/backup-firestore.mjs` reads the apiKey and projectId from there.
- Encryption: one key per user, `CryptoJS.AES.encrypt(JSON.stringify(value), key)` (OpenSSL "Salted__" format, `EVP_BytesToKey`/MD5, AES-256-CBC), on both `title` and `message` (`{login, password, description}`) of each item. Firestore `users/{uid}` = `{id, email, displayName, dateCreate, items: [{id: timestamp, title, message}]}`. The whole `items` array is rewritten on each change. Migration to v2: docs/CRYPTO.md §6.
- Known problems: [docs/SECURITY_AUDIT.md](docs/SECURITY_AUDIT.md).

## Work process

- The plan lives in [docs/ROADMAP.md](docs/ROADMAP.md): read it at the start of a session, keep "Текущий статус" and the checkboxes up to date, and record decisions in "Журнал решений".
- Each task: implement → `code-reviewer` agent → fixes → `task-verifier` agent → mark done. The `/next-step` skill runs this cycle.
- Decided: the app is never published (APK only); one UI language (Russian); no external links, "leave a review" button, or language switcher; no ads.
- **Architecture for all new code: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)** (FSD layers + class-based services behind interfaces, wired only in `app/di/container.ts`; RTK Query endpoints use `queryFn` with repositories from `extra`). Code rules: TS strict, no `let`, no `any`, no `@ts-ignore`, functional components only.
- Encryption, key handling, Firestore schema, migration and in-app backup: [docs/CRYPTO.md](docs/CRYPTO.md).
- Git: all rework happens on branch `feature/v2-rework`. Commit messages follow Conventional Commits (`feat:`, `fix:`, `refactor:`, `chore:`, `docs:`, `build:`, `test:`, `style:`, `perf:`, `ci:`; optional scope, e.g. `feat(crypto): ...`; imperative, English subject line). **Never commit or push without the user's explicit permission in the current conversation**: after a task is done, propose the commit message and wait.
- Telegram notifications: `.claude/hooks/telegram-notify.mjs` (Stop/Notification hooks), secrets in gitignored `.claude/telegram.json`.
- Data backup: `node scripts/backup-firestore.mjs` → `backups/` (gitignored, ciphertext only; v1 format until task 5.2 adds `entries`).
