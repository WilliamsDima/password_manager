# Цикл выполнения задачи из роадмапа

Аргумент (необязательно): id задачи, например `2.1`. Без аргумента берём первую `[ ]` по порядку.

1. **Выбор.** Прочитай `docs/ROADMAP.md` и `CLAUDE.md`. Назови пользователю задачу одной строкой.
   Если задача помечена «решение вместе с пользователем» или требует его действий
   (credentials, телефон), спроси или дай инструкцию и остановись.
2. **Реализация.** Сделай задачу. Ничего не пиши в Firebase, ничего не коммить без просьбы.
   Секреты (`firebase.ts`, `google-services.json`, `*.jks`, `.claude/telegram.json`) не трогай и не выводи.
3. **Ревью.** Запусти агента `code-reviewer`: передай id задачи и список изменённых файлов.
   Исправь всё из «Критично» и «Важно» (или объясни пользователю, почему нет). Если правки
   были существенными, запусти ревью повторно.
4. **Проверка требований.** Запусти агента `task-verifier`: передай id задачи, требования
   пользователя из разговора и краткое описание сделанного. Устрани найденные пробелы.
5. **Отметка.** В `docs/ROADMAP.md`: поставь `[x]` (только если verifier дал ✅; пункты 👤
   оставь `[ ]` с пометкой «ждёт пользователя»), обнови «Текущий статус», важные решения
   запиши в «Журнал решений».
6. **Отчёт пользователю** (кратко, по-русски): что сделано, итоги ревью и проверки, что
   нужно сделать ему, какая задача следующая.
7. **Коммит — только по разрешению.** Работаем в ветке `feature/v2-rework`. Предложи сообщение
   коммита по Conventional Commits (например `feat(crypto): add AES-GCM encryption`) и список
   файлов. `git commit` и `git push` выполняй **только после явного «можно» от пользователя**.
